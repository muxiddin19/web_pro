Lists & Conditional Rendering

Turn arrays into lists with .map(), and decide what to show with ternaries, && and early returns.

1. Rendering a list with .map()

Code
const courses = [
  { id: 1, name: 'Web Programming', credits: 3 },
  { id: 2, name: 'Databases',       credits: 3 },
  { id: 3, name: 'Algorithms',      credits: 4 },
];

function CourseList() {
  return (
    <ul>
      {courses.map(course => (
        // key: unique and stable, use the id
        <li key={course.id}>
          {course.name} — {course.credits} credits
        </li>
      ))}
    </ul>
  );
}
Result (live)
What .map() returns (static)
// An array of 3 elements:
[
  <li key="1">Web Programming — 3 credits</li>,
  <li key="2">Databases — 3 credits</li>,
  <li key="3">Algorithms — 4 credits</li>
]

// React puts that array inside the <ul>

Add a fourth course to the array, refresh the page, and a fourth line appears. You change the data, not the markup.

key = index (live)
key = id (live)
What you should see: after removing "Web Programming", the index list keeps the note "A" next to "Databases". React matched the boxes by position, so the first box stayed and the note now sits on the wrong course. The id list removes the box that belonged to the removed course, so "A" disappears with it and "B" stays next to "Databases". Index keys are only safe for a list that never reorders, adds or removes items.

2. Conditional rendering: ternary and &&

Code
function UserGreeting({ isLoggedIn, username }) {
  return (
    <div>
      {/* 1. Ternary: one of two options */}
      {isLoggedIn
        ? <h1>Welcome back, {username}!</h1>
        : <h1>Please log in</h1>
      }

      {/* 2. &&: only when truthy */}
      {isLoggedIn && <button>Log out</button>}
    </div>
  );
}

2b. A trap with &&

Code
const items = [];   // empty list

// Looks fine, but...
{items.length && <p>You have items</p>}

// Safe: make it a real true/false
{items.length > 0 && <p>You have items</p>}
Without > 0 (live)
With > 0 (live)

In JavaScript 0 && anything is 0, and React prints the number 0 on the page. false, null and undefined print nothing, but 0 does.

3. Early return

Code
function Dashboard({ isAdmin }) {
  // Handle the "no" case first and stop
  if (!isAdmin) return <p>Access denied</p>;

  // Only admins reach this line
  return <AdminPanel />;
}
Result (live, use the checkbox)
When to use which (static)

Ternary: choose between two small pieces of markup.

&&: show something or nothing.

Early return: a whole component changes, or you need to guard against missing data.

An early return goes outside the JSX, before the main return. It is a normal JavaScript if statement, not something inside { }.
