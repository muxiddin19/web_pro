JSX Visualized

You write JSX, Babel compiles it to plain JavaScript, and React draws the result.

Example 1: one element

1. JSX (what you write)
const name = 'Amir';

const element =
  <h1 className="title">
    Hello, {name}!
  </h1>;
2. Compiled (simplified, you never write this)
const name = 'Amir';

const element =
  React.createElement(
    'h1',
    { className: 'title' },
    'Hello, ', name, '!'
  );
3. Result (live React output)

Example 2: a component with several elements

1. JSX (what you write)
function App() {
  const user = 'Amir';

  return (
    <div className="app">
      <h1>Welcome, {user}!</h1>
      <p>Today: {new Date().toDateString()}</p>
      <img src="photo.jpg" alt="Profile" />
    </div>
  );
}
2. Compiled (simplified)
function App() {
  const user = 'Amir';

  return React.createElement(
    'div', { className: 'app' },
    React.createElement('h1', null,
      'Welcome, ', user, '!'),
    React.createElement('p', null,
      'Today: ', new Date().toDateString()),
    React.createElement('img',
      { src: 'photo.jpg', alt: 'Profile' })
  );
}
3. Result (live React output)

The live image uses a built-in placeholder instead of photo.jpg, because that file does not exist here.

JSX rules to remember

className, htmlFor

Use className instead of class, and htmlFor instead of for.

Self-close void tags

Write <img />, <input />, <br />.

One root element

Return a single parent, or wrap siblings in a Fragment <>...</>.

JS inside { }

Any JavaScript expression works: {user}, {new Date().toDateString()}.

Comments in JSX

Inside markup use {/* comment */}, not //.
