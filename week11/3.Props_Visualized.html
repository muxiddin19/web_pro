Props: Passing Data

Props pass data from a parent component to a child. Inside the child they are read-only.

1. A parent passes props like HTML attributes

Code
// Parent passes props
function App() {
  return (
    <div>
      <StudentCard name="Amir Tashkentov" year={2} />
      <StudentCard name="Gulnora Nazarova" year={3} />
    </div>
  );
}

// Child: destructured (preferred)
function StudentCard({ name, year }) {
  return (
    <div className="card">
      <h3>{name}</h3>
      <p>Year {year}</p>
    </div>
  );
}

// Same thing with the props object:
// function StudentCard(props) {
//   ... {props.name} ... {props.year} ...
// }
Result (live)
What each child receives (static)
// 1st card
props = {
  name: "Amir Tashkentov",
  year: 2
}

// 2nd card
props = {
  name: "Gulnora Nazarova",
  year: 3
}

Same function, different props, different output. Note year={2} uses curly braces so it is a number, while name="..." is a string.

1b. Props are read-only

Code
function MutateDemo(props) {
  function tryChange() {
    'use strict';
    props.name = 'Someone else';  // not allowed
  }
  // ...
}
Try it (live)
Rule

A child must never change its own props. In development, React freezes the props object, so the assignment above throws an error.

If a value needs to change, the parent passes a new value, or the component keeps its own state (next topic).

2. Default values

Code
function Button({
  label = 'Click me',
  color = 'blue',
  disabled = false
}) {
  return (
    <button
      style={{ background: color }}
      disabled={disabled}
    >
      {label}
    </button>
  );
}

3. props.children

Code
function Panel({ title, children }) {
  return (
    <div className="panel">
      <h2>{title}</h2>
      <div className="panel-body">
        {children}
      </div>
    </div>
  );
}

<Panel title="Week 11">
  <p>React session today</p>
  <ul>
    <li>Components</li>
    <li>Props</li>
  </ul>
</Panel>
Result (live)
What Panel receives (static)
props = {
  title: "Week 11",
  children: [
    <p>React session today</p>,
    <ul>...</ul>
  ]
}

The dashed orange box in the result is where {children} was placed. Everything between <Panel> and </Panel> ends up there.

Common mistakes: writing year="2" when you need the number {2}; forgetting the curly braces in {name}; writing {props.name} after destructuring (it is just {name}); and trying to change a prop inside the child.
